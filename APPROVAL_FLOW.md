# Approval Flow - Подтверждение планов

## ✅ Реализовано

### Backend (API)
1. **POST /api/tasks/[id]/approve** - Подтверждение задачи
   - Проверка прав (только партнер, не автор)
   - Проверка, что задача требует подтверждения
   - Обновление approvalStatus на 'approved'

2. **POST /api/tasks/[id]/decline** - Отклонение задачи
   - Проверка прав (только партнер, не автор)
   - Проверка, что задача требует подтверждения
   - Обновление approvalStatus на 'declined'

3. **POST /api/events/[id]/approve** - Подтверждение события
   - Аналогично задачам

4. **POST /api/events/[id]/decline** - Отклонение события
   - Аналогично задачам

### Frontend (UI)
1. **Чекбокс в формах**
   - TaskForm: "⏳ Требует подтверждения партнёра"
   - EventForm: "⏳ Требует подтверждения партнёра"
   - Желтый фон (amber-50) для выделения

2. **Кнопки approve/decline в модалках**
   - Показываются только партнеру (не автору)
   - Только для pending статуса
   - Заменяют обычные кнопки редактирования/удаления

3. **Визуальные статусы** (уже были)
   - ⏳ Ожидает подтверждения [Имя партнера]
   - ✅ Принято
   - ❌ Отклонено

## 🎨 UI/UX особенности

### Логика отображения кнопок

#### Для автора задачи/события:
- Видит обычные кнопки (Редактировать, Завершить, Удалить)
- Видит статус подтверждения в карточке

#### Для партнера (если pending):
- Видит кнопки "✅ Подтвердить" и "❌ Отклонить"
- НЕ видит кнопки редактирования/удаления

#### После подтверждения/отклонения:
- Все видят обычные кнопки
- Статус отображается в карточке

### Toast уведомления
- "Задача подтверждена!" (success)
- "Задача отклонена" (info)
- "Событие подтверждено!" (success)
- "Событие отклонено" (info)

## 🚀 Как использовать

### Создание задачи с подтверждением
1. Открыть форму создания задачи
2. Заполнить данные
3. Поставить галочку "⏳ Требует подтверждения партнёра"
4. Создать задачу

### Подтверждение задачи партнером
1. Партнер видит задачу со статусом "⏳ Ожидает подтверждения [Ваше имя]"
2. Открывает задачу
3. Видит кнопки "✅ Подтвердить" и "❌ Отклонить"
4. Нажимает одну из кнопок
5. Статус обновляется

### Логика работы
- Автор НЕ может подтвердить/отклонить свою задачу
- Только партнер может подтвердить/отклонить
- После подтверждения/отклонения статус меняется
- Задачу можно редактировать/удалять независимо от статуса

## 🔒 Безопасность

### Проверки на backend
- Авторизация (токен)
- Членство в паре
- Проверка, что задача требует подтверждения
- Проверка, что пользователь не автор
- Проверка существования задачи/события

### Проверки на frontend
- Кнопки показываются только партнеру
- Кнопки показываются только для pending статуса
- Toast уведомления об ошибках

## ✨ Особенности реализации

### Гибкость
- Можно создавать задачи с подтверждением и без
- Можно редактировать задачу и изменить requiresApproval
- Статус approvalStatus независим от status задачи

### Масштабируемость
- Легко добавить approval для других сущностей (notes, shopping)
- Можно добавить историю подтверждений
- Можно добавить уведомления о подтверждении
